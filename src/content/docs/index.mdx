## The rule this course is built on

No concept is introduced before you have **seen the failure that requires it**. Ten of the eleven
modules open on the previous one's measured wall; module 2 is the one declared exception, and says
so on its own page — it exists to earn one sentence three later gates spend.

**bare LLM** → *it invents a penalty, then abstains, in the same voice* → **what a weight is** →
*a weight is a frozen photograph* → **fine-tuning** → *the photograph is of last quarter, and it
can cite nothing* → **stuff the prompt** → *it fits, and you pay for the whole book on every
question* → **keyword search** → *hit@1 0.000 on the six Turkish questions about English
documents* → **naive RAG** → *hit@1 0.600 over 28 whole documents* → **the right embedder** →
*ChromaDB's default gets none of those six, `bge-m3` gets two, and whole documents are still
0.600* → **structure-aware chunking** → *hit@1 0.700, in a Python list that dies with the
process* → **ChromaDB** → *storage is settled, 0.700 is not* → **hybrid + rerank** → *fusion
loses, the reranker only levels, and `multi_hop` is still 0.000* → **agentic RAG**.

Every gap there is 0.05 or a multiple of it — one question in twenty. Read the direction, not the
digit.

## How the day runs

There are exactly two surfaces, and the repository root anchors both. **A terminal at the
repository root** — the folder holding `corpus/`, `notebooks/`, `eval/` and `exercises/` — runs
every `ollama …` command and everything written as `python scripts/…`, `python exercises/…` or
`python eval/…`. **VS Code, with that same repository root as the open folder**, runs the nine
notebooks: percent-format `.py` files under `notebooks/`, where you put the cursor in a `# %%`
block and press `Shift+Enter`. No Jupyter server, no browser notebook, no cloud console.
[Setup](/modules/00-setup/) walks both in full; the only dependencies are `numpy` and `chromadb`.

Setup is pre-work, done at home the evening before. In the room the day opens at 09:10 with ten
minutes of everyone running `verify_setup.py` at once; module 1 then starts on a cold model.

`UNVERIFIED: the plan opens at 09:00 with a ten-minute demo of the finished agent. No page on this site carries that material, so the day as written begins at 09:10.`

Three of the day's results are things you *run* rather than things you build, so they live in
`exercises/` as one terminal command each:

| Module | Command | Roughly |
|---|---|---|
| 6 — is the default embedder right for your language? | `python exercises/m6_embedding_bakeoff.py` | ~18 s |
| 7 — why did retrieval bring back garbage? | `python exercises/m7_chunking_ladder.py` | ~50 s |
| 9 — when does a reranker actually pay? | `python exercises/m9_rerank_trade.py` | ~4 min |

M-series Mac, models already resident; considerably longer on a CPU-only laptop. The rule behind
the split:

> If it is a **measurement**, you run one command and we compare numbers.
> If it is a **mechanism**, we build it together in cells.
